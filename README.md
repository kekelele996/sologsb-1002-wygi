# 学术论文协作审阅台

面向作者、审稿人与编辑三类角色的论文协作审阅前端。正文、批注、讨论、建议、版本和冲突处理数据均保存在浏览器本地。

## 功能

- 三个独立工作区：
  - 作者可直接修改正文，逐条接受或拒绝审稿人的修改建议。
  - 审稿人可引用原文、添加段落批注、提出修改建议并回复讨论。
  - 编辑可合并同一段落的重复意见、锁定已确认段落并比较两个版本。
- 侧边目录、段落高亮、批注过滤、修订模式与版本差异表。
- `J` / `K` 在段落之间导航，`T` 切换修订模式，编辑角色可用 `L` 锁定或解锁段落；`Ctrl/⌘ + Z` 撤销，`Ctrl/⌘ + Y` 或 `Shift + Z` 重做。
- 完整撤销重做、手动保存和浏览器未保存提醒。
- 草稿自动写入 `localStorage`，刷新或断网后仍可继续。
- 内置模拟接口。点击“模拟冲突”会让远端协作者修改当前段落，并展示本页版本与远端版本，可选择保留任一方。
- 页面包含完整的示例论文、批注、回复、重复意见和两个历史版本。

## 离线批注同步

编辑部版本库（合订稿 + 段落修订号）与审稿人离线批注稿（批注、引用片段、待同步队列）是两个各自持久化的本地仓库，回网后按段落修订号对账：

- 头部开关切换审稿人在线/离线；离线时批注只写入本机批注稿并进入待同步队列，同一段落的多次批注会先并成一条。
- 回网（或在“离线同步”面板点“立即同步”）后逐条对账：合订稿该段修订号未变则并入批注并推进修订号；已被编辑部改过则两边都保留，挂起等编辑定夺，批注稿不会覆盖合订稿。
- 勾选“模拟提交中断”可演示部分失败：已并入的出队不重发，没送上去的留在队列里重试。
- 冲突由编辑角色在面板中定夺（仍并入批注 / 保留合订稿），处理结果记入同步日志。
- 旧版批注稿没有修订号，升级时自动按合订稿现版本补上；“模拟旧版批注升级”可演示迁移过程。

## 技术栈

- React 19
- Vite + TypeScript
- Zustand
- Ant Design
- localStorage + 浏览器内模拟接口

## 本地开发

```bash
npm install
npm run dev
```

开发端口由 Vite 决定，源码不硬编码宿主端口。

## 生产构建

```bash
npm install
npm run build
npm run preview
```

## Docker

```bash
docker build -t sologsb-1002 .
docker run --rm -p 10002:80 sologsb-1002
```

容器内的 nginx 监听 `80`，访问 `http://localhost:10002`。
